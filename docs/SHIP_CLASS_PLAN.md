# 同型船の不具合調査：設計メモ（ネタバレを含む）

2026-10-19 に合意した方向をまとめたものです。同日に 1〜5 を実装しました。実装で決めた値と、メモからの変更は次のとおりです。

- 不具合Cは、温度センサーの校正ではなく **冷却調整装置の最大流量（30 → 16 L/min）** にしました。校正のずれ（−3 °C）では、冷却調整装置が補ってしまい、暑い航路でも過熱による発火しなかったためです。
- 航路は、操縦室（操縦担当のクルーの部屋）の **航路操作卓** で選びます（涼しい・標準・暑い）。指示書の新しい機能ではなく、ふつうの操作卓の操作です。放熱器は航路の基準温度（16・18・22 °C）に船の外の温度変化（0〜4 °C）を加えます。
- 過熱による発火は「電子機器の温度 42 °C 以上が 3 tick」、引火は「酸素濃度 30 % 以上で実験運転の開始」、爆発は「火災 5 tick」です。
- 報告の日の結果（3つの不具合が同時に入った在庫船）：3号の日は t=46 に過熱による発火で火災、t=51 に爆発。5号の日は t=64 に引火、t=68 に爆発。8号の日は t=50 前後に過熱による発火。正常な船は、どの日・どの航路でも爆発しません。
- 不具合Bの代替修理は用意していません（直接の修理のみ）。3号の代替修理「最低流量 20」は、8号の冷却不足も補います。
- 演出のうち、配置図の上で船が壊れて飛び散る絵はまだありません（爆発のダイアログに破片の演出を付けています）。

以下は、合意時のメモです（不具合Cの記述は旧案のまま残しています）。

## 1. 設定

- プレイヤーは、造船会社の**不具合調査メカニック**です。
- 自社の同型船「カナリア級」で、不具合の報告が相次いでいます。何隻かは爆発四散しました。乗員は全員、脱出ポッドで無事でした。
- 会社は在庫の同型船を**試験航海**に出して、不具合を再現させます。
  - 雇われたクルーが、メカニックの書いた**指示書**どおりに操作卓を操作します。
  - メカニックも毎回その船に乗り込み、部屋を移動しながら表示を見て、整備区画の設備を点検します。
- 再現できれば、船は爆発します。爆発の前に、クルーとメカニックは脱出ポッドで逃げ、クルーは文句を言います。
- 直せれば、何事もなく帰港します。クルーは退屈そうにしています。
- 在庫船の数に上限は付けません。「本日の爆発：12 隻」のような集計を、笑いとして表示するだけです。

トーンは漫画的にします。誰も死なず、些細な原因で船が派手に壊れることを笑えるようにします。

## 2. 用語（「用語：クルーとメカニック」の更新）

| 用語 | 意味 |
|---|---|
| クルー | 試験航海に雇われた乗員。役割（科学・生命維持・電力・冷却）ごとに自分の部屋を持つ。指示書どおり自分の部屋の操作卓を操作し、自分の部屋の表示を見る。inner ノードには操作も参照もできない |
| メカニック | プレイヤー。毎回試験航海に乗り込む。船外以外のすべての部屋に入れる。inner ノードを点検し、設定を変えられる |
| 試験航海 | 今の「実験」。在庫船1隻を同じ初期状態から出して、指示書どおりに操作する |
| 指示書 | 今の「操作シーケンス」。どの tick に、どの部屋の操作卓で、何をするか |
| 指示書の書き換え | 今の「変種」。元の指示書は残る |
| 航海記録 | 今の「実験の結果」。表示の時系列、警報、爆発した時刻と原因 |
| 不具合報告 | 今の「障害レポート」。実際に不具合が起きた船のクルーが、自分の部屋で見たことだけを書く |
| 航路 | 外乱（戻り冷却水の温度の揺らぎ）のシード。同じ航路なら同じ揺らぎになる |

- これで、Run / Pause を除いた実験の道具はすべて物語の中の道具になります。Run / Pause / 速度は、引き続き物語の外の道具です。
- 修理は、メカニックが試験航海中の船の設定を変えることです。合格基準をすべて満たし、かつ爆発しなければ、改修通知を発行してクリアになります。

## 3. 爆発に至る共通の仕組み（新規）

爆発は唐突に起こさず、一段ずつ悪化するのを見せてから起こします。どの段も、どこかの部屋の表示か、設備パネルで見えるようにします。

| 段 | 仕組み（仮の値） | どこで見えるか |
|---|---|---|
| 過熱による発火 | 電子機器の温度が 42 °C を超えた状態が 3 tick 続くと、電子機器が発火する | 冷却管理室（安全監視用の温度）、電子機器室の電子機器 |
| 酸素の滞留 | 酸素タンクが満杯になると、逃がし弁が電子機器室へ酸素を放出する（コスト削減のための仕様）。換気ファンが船外へ排出する | 電子機器室の新しい設備「換気ファン」「電子機器室酸素濃度」 |
| 火花 | 実験装置が実験運転を始めるとき、起動電流で火花が出る | 実験室（実験装置の状態の切り替わり） |
| 火災 | 電子機器室の酸素濃度が 30 % 以上のときに火花か過熱による発火が起きると、火災になる。過熱による発火は、酸素濃度に関係なく火災になる | 全部屋に警報 |
| 爆発 | 火災が 5 tick 続くと、船が爆発する。その時点で試験航海の記録を止める | 全画面の演出 |

- 爆発したら、その試験航海はその tick で終わります。航海記録には、「何 tick で爆発」と「火災の原因（過熱による発火か火花か）」を残します。
- 比較表には爆発の時刻が並ぶので、どの指示書で壊れたかがひと目でわかります。
- 正常な船は、どの公開検証ケースでも火災にならないようにします。過熱による発火のしきい値と、ファンの排出量に余裕を持たせます。

## 4. 不具合（複数）

同じ製造ロットの在庫船には、**3つの不具合が同時に入っています**。報告はそれぞれ別の船・別の日から来ます。

各不具合は、別々の操作条件でだけ表に出るように設計します。そうすれば、試験航海で1つずつ切り分けられます。1つ直すと、同じ指示書でも別の原因で爆発したり、爆発が遅れたりします。この「直したのに、まだ爆発する。でも今度は時刻が違う」も、発見の一つとして使います。

### 不具合A：冷却水ポンプの優先度（既存の案件を拡張）

| 項目 | 内容 |
|---|---|
| 故障 | 配電盤で、冷却水ポンプが最優先の機器ではなくふつうの機器になっている |
| 再現条件 | 実験運転を始めた数 tick 後に 酸素 増産を始める。増産が遅ければ起きない |
| 連鎖 | 酸素 増産が先に船の電気を確保する → ポンプが使ってよい電力が頭打ちになる → 冷却水の流量が不足する → 電子機器の温度が 42 °C を超える → 過熱による発火 → 火災 → 爆発（実験開始から約 40 tick 後） |
| 手掛かり | 冷却管理室の冷却水の流量が正常な日の半分程度。ポンプは「運転中」のまま。電力管理室では電気の使用量が上限付近 |
| 直接の修理 | 優先度を最優先の機器に戻す。今の代替修理（増産の申請する電力を下げる、最低流量を上げる）も認める |

### 不具合B：換気ファンの強さ

| 項目 | 内容 |
|---|---|
| 故障 | 電子機器室の換気ファンの強さが、仕様の 1.5 L/min ではなく 0.3 L/min になっている |
| 再現条件 | 酸素 増産を長く続けてタンクを満杯にしたあとで、実験運転を始める。順番が逆なら起きない。不具合Aとは逆の順番 |
| 連鎖 | 増産を続ける → タンクが満杯になる → 逃がし弁が電子機器室へ放出する → ファンが追いつかず、酸素濃度が上がる → 実験運転を始めた火花 → 火災 → 爆発（実験開始の直後） |
| 手掛かり | 生命維持室のタンク残量が 100 % のまま。爆発が実験開始の直後に起きる（不具合Aでは数十 tick 後）。電子機器室の酸素濃度の設備パネル |
| 直接の修理 | ファンの排出量を 1.5 に戻す。代替：逃がし弁の作動残量を 100 % より上にする設定があれば、それも可（要検討） |
| 帳尻合わせ（不合格） | 実験運転をしない。実験装置を止めておく |

### 不具合C：温度センサーの校正

| 項目 | 内容 |
|---|---|
| 故障 | 温度センサーの表示のずれの補正が 0 ではなく −3 °C で、実際より低く報告する |
| 再現条件 | 暑い航路（戻り冷却水の温度が高めに揺らぐ航路）で、実験運転を長く続ける。涼しい航路では起きない |
| 連鎖 | センサーが低く報告する → 冷却調整装置が流量を上げきらない。実験装置の過熱防止も遅れる → 暑い航路では電子機器の温度が 42 °C を超える → 過熱による発火 → 火災 → 爆発 |
| 手掛かり | 冷却管理室の安全監視用の温度と、設備パネルで見えるセンサーの報告値がずれている。航路によって結果が変わる |
| 直接の修理 | オフセットを 0 に戻す |
| 必要な新機能 | 指示書で航路を選べるようにする（今は外乱のシードを変えられない） |

### 案件の分け方（2026-10-20 変更）

1つの画面で扱う不具合は1つにしました。船の構造（設備・部屋・合格基準・公開の試験航海）は全案件で共通です。各案件は故障のない船にその案件の不具合だけを入れて始め、前の案件の修理は持ち越しません。

| 順番 | 案件 | 不具合 | 報告 |
|---|---|---|---|
| 1 | カナリア3号の爆発 | A（冷却水ポンプの優先度） | 実験担当・冷却担当・電力担当の3件 |
| 2 | カナリア5号の爆発 | B（換気ファンの強さ） | 生命維持担当・実験担当の2件 |
| 3 | カナリア8号の爆発 | C（冷却調整装置の最大流量） | 操縦担当・冷却担当の2件 |
| 4 | 同じ症状の2隻 | A と C | 11号（冷却・生命維持）と12号（冷却・航法）の4件 |

理由：不具合が3つ同時に入っていると、1つの条件だけを変えた試験航海でも別の不具合で爆発し、比べた結果が読めなくなるためです。また、1つ直しても残りで爆発が続き、修理が正しかったかが分かりません。

最後の案件は、どちらも「冷却水の流量が増えずに過熱」という同じ症状で、止まる流量（12 L/min と 16 L/min）とその日の指示（酸素の増産・暑い航路）が違います。どの報告がどの不具合かを見分けることが課題です。A だけ、または C だけを直すと、もう片方の日の指示書で爆発します。

各案件の代替修理：3号は 酸素の増産時に申請する電力を 3.5 kW 以下、または最低流量 20 L/min 以上でも合格します。8号は最大流量 24 L/min 以上なら合格し、最低流量を上げるだけでは足りません。5号は換気ファンを戻す以外の修理はありません。

故障のない船は、ランダムな指示書 25 本（テスト）で、合格基準を守り爆発しないことを確かめています。

## 5. 演出

| 場面 | 演出 |
|---|---|
| 悪化の途中 | 表示に警報が出る。各部屋のクルーの声（「ちょっと暑くない？」「タンクがずっと満タンなんだけど」）。ほかの部屋の警報は、部屋の名前だけを知らせる |
| 火災 | 全部屋に警報。部屋の色が変わる。クルーが騒ぐ |
| 爆発 | 配置図の船が壊れて飛び散る。脱出ポッドが飛び出す。クルーの文句（「だから言ったのに」）。航海記録に「t=48 爆発（電子機器室の過熱による発火）」 |
| 修理後の確認 | 同じ指示書で試験航海を出すと、何事もなく帰港する。クルーは退屈そう。爆発していた時刻に「何も起きなかった」と表示して対比を見せる |
| 集計 | 「本日の爆発：n 隻」。上限なし |

演出は、因果の順番がわかるように出します。たとえば、爆発の直前に「流量不足 → 温度上昇 → 過熱による発火」の順に、関係した部屋を光らせます。

## 6. 実装の順番（案）

1. 爆発に至る共通の仕組み（電子機器室酸素濃度、換気ファン、火花、火災、爆発）をエンジンの上に作り、正常な船で爆発しないことをテストする。
2. 不具合A・B・Cを入れ、各報告の日が狙った原因で最初に爆発するよう数値を調整する。
3. 航路の選択を指示書に足す（不具合Cのため）。
4. 言葉を「試験航海」「指示書」「航海記録」などに置き換える。
5. 演出（警報、クルーの声、爆発、帰港、集計）を足す。

## 7. 未確認・要検討
