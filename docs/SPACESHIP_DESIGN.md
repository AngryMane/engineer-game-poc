# 宇宙船PoC 設計資料（公開してよい内容）

変更要求書「engineer-game-poc 宇宙船テーマへのPoC再構築」（対象 main `dc3a5f3`）への対応記録です。解答・再現手順は [SPACESHIP_SPOILERS.md](SPACESHIP_SPOILERS.md) に分けてあり、この資料には書きません。

## 1. 着手時に確認した、保持するAPI・テスト・保存形式

| 対象 | 保持の方針 |
|---|---|
| `engine.ts` の `createWorld` / `step` / `setInput` / `intervene` / `requestNode` / `restartWithSettings` / `validateBehavior` | 署名と意味を変えない。1 tick 単位の決定論的処理、同期問い合わせ、外乱シード、出力契約による検証はそのまま。 |
| `Expr` と数値演算 | 内部計算に再利用する。新しい演算子は追加していない。 |
| `experiment.ts`（操作列・再生・変種・比較） | 変更なし。宇宙船でもそのまま動く。 |
| `hierarchy.ts`（階層・境界観測・仕様） | 出力ポートが状態キー（`key`）を指定できるようにしただけ。既存シナリオの表示は変わらない。 |
| 保存形式 | 旧: `causal-hierarchy-session-v15`（v14 から移行可）。宇宙船は新キー `causal-ship-session-v16`・`version:16`。旧データは読み書きせず残す。 |
| テスト | 既存の 214 件はすべて残し、通る状態を保つ（CPU 負荷で 5 秒を超えがちな 2 件だけタイムアウトを明示）。旧シナリオ群は回帰用 fixture として残る。 |

## 2. 意味を伴うメッセージ（`src/signals.ts`）

- 接続（`Connection`）は `signal`（信号辞書の ID）を持てます。ノードは `signals.in`（入力名ごとに期待する信号）と `signals.out`（状態キーごとに送る信号）を宣言します。`sourceKey` で `value` 以外の状態を送れます（例：ポンプは流量・電力要求・状態報告の3種類を送る）。
- 信号定義は `label`・`unit`・`valueType`・`kind`（計測報告／指令／状態通知／応答／物理量）・`meaning`。enum は値ごとの表示名を持ちます。
- 配送されたメッセージは接続ごとに直近 32 件を `world.messages` に記録します。各記録は送信元、**計測時刻**（計測報告のみ）、**送信時刻**、**受信時刻**、通し番号を持ちます。計算時には、受信側の `frames[node].adopted` に「どのメッセージを採用したか」と**採用時刻**を残します。
- 計測時刻は、センサーが読んだ値が物理側で計算された時刻です。例：ラック温度は t=11 に計算され、センサーが t=12 に読んで送信し、t=13 に冷却制御へ届き、冷却制御は次の報告が届くまで t=14〜16 もその値を採用し続けます。
- 定義時の検査：未定義の信号、辞書と異なる単位、送信側・受信側の宣言と異なる信号（例：温度報告を電力要求の入力に接続）をエラーにします。メッセージには単位変換を含めません。単位をまたぐ計算はノードの式に書きます。
- **未対応**：同じ信号を異なる単位で表すこと（°C と K など）、複数の信号を1つの入力に合算すること（合算自体は許すが、意味の整合は検査しない）、enum の値域検査。
- 信号辞書を持たないシナリオ（旧PoC）では何も記録せず、値は単位なしの数値のまま表示します。旧データを温度などに見せかけることはしません。

## 3. 宇宙船の機能仕様

1 tick は制御周期1回です。メッセージは送信の次の tick に届きます。数値はゲーム内の規則で、工学的な精度は目指していません。規則はすべて各モジュールの Spec に掲載しています。

| モジュール | 設備（ノード） | 役割 |
|---|---|---|
| 環境計測 | ラック温度センサー、主バス電力計 | 4 tick ごとにラック温度、2 tick ごとに主バス負荷を計測して報告する |
| 熱制御 | 機器ラック、冷却制御、冷却ポンプ | 温度報告から流量指令を決め、ポンプは給電許可の範囲で冷却液を流す。ラックの温度は発熱と冷却の差で変わる |
| 生命維持 | O₂生成装置 | 通常 1 kW、増産 4 kW を要求し、給電許可に比例して酸素を生成する |
| 配電 | 配電盤 | 容量 5.5 kW。重要負荷（冷却ポンプ）を毎 tick 先に満たし、残りを一般負荷（O₂生成装置）へ先着順で割り当てる |
| 科学ペイロード | 科学ペイロード | 実験運転で 2 kW の熱を出す。温度報告が 42 °C 以上で熱保護の制限運転、36 °C 以下で復帰 |
| System 直下 | ペイロード運転指令、O₂生成モード指令、放熱ループ温度（外乱 18〜22 °C）、5つの報告先 | 運用担当の操作と、船外環境 |

変更要求書の候補「運転制御」は、独立モジュールにすると指令を中継するだけの無意味なノードになるため、指令は System 直下の入力に置き、5番目のモジュールを推理に関わる「科学ペイロード」にしました。

| 状態 | ラック温度 | 流量 | ポンプ電力 | O₂生成 | 主バス |

### 運用契約（System の公開仕様。クリア判定の根拠）

| 報告先 | 契約 |
|---|---|
| 機器ラック温度（独立監視） | 常に 15〜40 °C |
| ペイロード状態 | 指令の3 tick後に指令どおり。制限運転は不可 |
| O₂生成量 | 通常 0.5 L/min 以上、増産指令の5 tick後から 0.8 L/min 以上、上限 2 L/min |
| 冷却ポンプ状態 | 運転中 |
| 主バス負荷 | 0〜5.5 kW（定格） |

公開検証ケースは 13 件です（順序の両方向、0〜40 tick の間隔、待機→実験、増産の停止と再開、実験の停止と再開、300 tick の長時間運転、外乱シード2種）。ケースの操作列は画面の初期表示に出しません。

## 4. 画面

- 開始画面は宇宙船の設備系統図と障害レポート3件。ノードは設備名、値は単位付き（enum は表示名）で表示し、未受信は「未受信」「初期値」と書きます（0 と混同しない）。
- 境界ポートと入力欄には「採用 t=…（送信 t=…・計測 t=…）」を表示します。接続をクリックすると、信号の意味・種別・単位、最新の値と計測／送信／受信／採用時刻、受信履歴を表示します。
- Messages タブは、いま開いている階層の中と境界を通るメッセージを、人が読める文で新しい順に表示します。物理量は初期状態で非表示、「値が変わったときだけ」を切り替えられます。
- 時間操作は Run / Pause / Reset / Restart と 1x/4x/8x のみです。実験の記録・再生・変種・比較は既存のまま使えます。
- 宇宙船は Mode A/B を持たず、意味のある表示だけです。旧PoC（抽象）の2ページは選択肢の下に残しています。
- 故障箇所の自動着色・自動列挙はしません（契約違反の報告先だけが警告表示になります）。

## 6. 評価について

再現条件の発見と因果説明の二段階の洞察が起きるか、宇宙船の意味が推理を助けるかは、**初見プレイテストをしていないため未検証**です。テストで確かめたのは、仕様どおりに動くこと、再現・対照の操作列が決定論的に同じ結果になること、修復判定が代替修復を受理し帳尻合わせを落とすことまでです。
