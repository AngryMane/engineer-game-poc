# 宇宙船PoC 設計資料（公開してよい内容）

変更要求書「engineer-game-poc 宇宙船テーマへのPoC再構築」（対象 main `dc3a5f3`）への対応記録です。解答・再現手順は [SPACESHIP_SPOILERS.md](SPACESHIP_SPOILERS.md) に分けてあり、この資料には書きません。

## 用語：クルーとメカニック

| 用語 | 意味 | システムに対してできること |
|---|---|---|
| クルー | 試験航海に雇われ、この宇宙船に乗ってシステムを利用する人。役割（航法・科学・生命維持・電力・冷却）ごとに自分の部屋を持ち、指示書どおりに操作卓を操作する | 自分の部屋の操作卓の input ノードを操作し、自分の部屋の表示で output ノードを見る。inner ノードは操作も参照もできない |
| メカニック | プレイヤーのアバター。造船会社の不具合調査メカニックで、毎回試験航海に乗り込む。クルーの一員 | 船外以外のすべての部屋（クルーの部屋と整備区画）に入れる。いる部屋の操作卓と表示を使い、inner ノードに干渉できる |

- メカニックの「干渉」は、inner ノードの入力・出力・プロパティ（設定と内部状態）をすべて見ることと、変更できると定めた設定だけを変える（修理）ことです。計算する間隔などの設定と内部状態は、見るだけで変えられません。
- 船外の放熱器（戻り冷却水の温度）は input ノードですが外乱で、クルーもメカニックも操作できません。
- 障害レポートはメカニック以外のクルーが書いたものなので、input と output の値だけで書きます。
- 実験は「試験航海」、操作シーケンスは「指示書」、変種は「書き換えた指示書」と呼び、物語の中の道具として扱います。Run / Pause / 速度は、物語の外にあるプレイヤーの道具です。
- 火災警報は船内全体に出る表示で、どの部屋でも見えます。船が爆発すると、その試験航海はその tick で終わります。

## 1. 着手時に確認した、保持するAPI・テスト・保存形式

| 対象 | 保持の方針 |
|---|---|
| `engine.ts` の `createWorld` / `step` / `setInput` / `intervene` / `requestNode` / `restartWithSettings` / `validateBehavior` | 署名と意味を変えない。1 tick 単位の決定論的処理、同期問い合わせ、外乱シード、出力契約による検証はそのまま。 |
| `Expr` と数値演算 | 内部計算に再利用する。新しい演算子は追加していない。 |
| `experiment.ts`（操作列・再生・変種・比較） | 変更なし。宇宙船でもそのまま動く。 |
| `hierarchy.ts`（階層・境界観測・仕様） | 出力ポートが状態キー（`key`）を指定できるようにしただけ。既存シナリオの表示は変わらない。 |
| 保存形式 | 旧: `causal-hierarchy-session-v15`（v14 から移行可）。宇宙船は新キー `causal-ship-session-v16`・`version:16`。旧データは読み書きせず残す。 |
| テスト | 既存の 214 件はすべて残し、通る状態を保つ（CPU 負荷で 5 秒を超えがちな 2 件だけタイムアウトを明示）。旧シナリオ群は回帰用 fixture として残る。 |

## 2. 意味を伴うメッセージ（`src/signals.ts`）

- 接続（`Connection`）は `signal`（信号辞書の ID）を持てます。ノードは `signals.in`（入力名ごとに期待する信号）と `signals.out`（状態キーごとに送る信号）を宣言します。`sourceKey` で `value` 以外の状態を送れます（例：ポンプは流量・電力申請・状態報告の3種類を送る）。
- 信号定義は `label`・`unit`・`valueType`・`kind`（測定値の報告／指示／状態の報告／応答／実際の値）・`meaning`。enum は値ごとの表示名を持ちます。
- 配送されたメッセージは接続ごとに直近 32 件を `world.messages` に記録します。各記録は送信元、**計測時刻**（測定値の報告のみ）、**送信時刻**、**受信時刻**、通し番号を持ちます。計算時には、受信側の `frames[node].adopted` に「どのメッセージを採用したか」と**採用時刻**を残します。
- 計測時刻は、センサーが読んだ値が物理側で計算された時刻です。例：電子機器の温度は t=11 に計算され、センサーが t=12 に読んで送信し、t=13 に冷却調整装置へ届き、冷却調整装置は次の報告が届くまで t=14〜16 もその値を採用し続けます。
- 定義時の検査：未定義の信号、辞書と異なる単位、送信側・受信側の宣言と異なる信号（例：温度報告を電力申請の入力に接続）をエラーにします。メッセージには単位変換を含めません。単位をまたぐ計算はノードの式に書きます。
- **未対応**：同じ信号を異なる単位で表すこと（°C と K など）、複数の信号を1つの入力に合算すること（合算自体は許すが、意味の整合は検査しない）、enum の値域検査。
- 信号辞書を持たないシナリオ（旧PoC）では何も記録せず、値は単位なしの数値のまま表示します。旧データを温度などに見せかけることはしません。

## 3. 宇宙船の機能仕様

1 tick は制御周期1回です。メッセージは送信の次の tick に届きます。数値はゲーム内の規則で、工学的な精度は目指していません。規則はすべて各モジュールの Spec に掲載しています。

| モジュール | 設備（ノード） | 役割 |
|---|---|---|
| 環境計測 | 温度センサー、電力計 | 4 tick ごとに電子機器の温度、2 tick ごとに電気の使用量を計測して報告する |
| 冷却 | 電子機器、冷却調整装置、冷却水ポンプ | 温度報告から流量指示を決め、ポンプは使ってよい電力の範囲で冷却水を流す。電子機器の温度は発熱と冷却の差で変わる |
| 生命維持 | 酸素製造装置 | 通常 1 kW、増産 4 kW を要求し、使ってよい電力に比例して酸素を製造する |
| 配電 | 配電盤 | 容量 5.5 kW。最優先の機器（冷却水ポンプ）を毎 tick 先に満たし、残りをふつうの機器（酸素製造装置）へ早い者順で割り当てる |
| 実験装置 | 実験装置 | 実験運転で 2 kW の熱を出す。温度報告が 42 °C 以上で過熱防止の出力制限、36 °C 以下で復帰 |
| System 直下 | 実験装置の運転指示、酸素製造モードの指示、戻り冷却水の温度（外乱 18〜22 °C）、5つの報告先 | クルーの操作と、船外環境 |

変更要求書の候補「運転制御」は、独立モジュールにすると指示を中継するだけの無意味なノードになるため、指示は System 直下の入力に置き、5番目のモジュールを推理に関わる「実験装置」にしました。

### 正常状態の目安

| 状態 | 電子機器の温度 | 流量 | ポンプ電力 | 酸素製造 | 船の電気 |
|---|---|---|---|---|---|
| 待機中（初期） | 30 °C | 10 L/min | 1.25 kW | 0.5 L/min | 2.25 kW |

### 合格基準（System の公開仕様。クリア判定の根拠）

| 報告先 | 契約 |
|---|---|
| 電子機器の温度（安全監視用） | 常に 15〜40 °C |
| 実験装置の状態 | 指示の3 tick後に指示どおり。出力制限は不可 |
| 酸素の製造量 | 通常 0.5 L/min 以上、増産指示の5 tick後から 0.8 L/min 以上、上限 2 L/min |
| 冷却水ポンプの状態 | 運転中 |
| 電気の使用量 | 0〜5.5 kW（上限） |

公開検証ケースは 13 件です（順序の両方向、0〜40 tick の間隔、待機→実験、増産の停止と再開、実験の停止と再開、300 tick の長時間運転、外乱シード2種）。ケースの操作列は画面の初期表示に出しません。

## 4. 画面

開始画面の検討（8案）は [OPENING_SCREEN_OPTIONS.md](OPENING_SCREEN_OPTIONS.md) にあります。採用したのは「船内配置図＋部屋の表示＋設備パネル」の組み合わせで、見た目はまだ箱と区画だけの粗いものです。

- **部屋と役割**：

  | 部屋 | 種類 | 操作卓（input） | 表示（output） |
  |---|---|---|---|
  | 操縦室 | 操縦担当のクルーの部屋 | 航路操作卓（涼しい・標準・暑い航路） | 戻り冷却水の温度 |
  | 実験室 | 実験担当のクルーの部屋 | 実験装置の操作卓、データ記録卓 | 実験装置の状態、記録済みデータ量 |
  | 生命維持室 | 生命維持担当のクルーの部屋 | 酸素製造の操作卓（酸素製造モード） | 酸素の製造量、酸素タンクの残量 |
  | 電力管理室 | 電力担当のクルーの部屋 | 最大値表示の操作卓 | 電気の使用量、電気の使用量の最大値 |
  | 冷却管理室 | 冷却担当のクルーの部屋 | — | 電子機器の温度（安全監視用）、冷却水ポンプの状態、冷却水の流量 |
  | 電子機器室・生命維持機械室・電源室・冷却装置区画 | 整備区画（メカニックだけ） | — | — |
  | 船外 | 誰も入れない | — | — |

  inner の設備はすべて整備区画にあり、操作卓はすべてクルーの部屋にあります（シナリオ検証で確かめます）。
- **部屋の表示**：いる部屋の表示だけを見られます。時系列グラフ、Output log、Messages タブも、いる部屋の表示（と、選んだ設備の入力・出力）に絞ります。ほかの部屋で警報が出ていると、部屋の名前だけを知らせます。合格基準（クリア条件）はどの部屋でも読めます。
- **移動**：配置図の部屋をクリックすると移動します。移動に時間はかかりません。設備をクリックすると、その設備の部屋に移動してパネルを開きます。
- **操作卓**：いる部屋の操作卓だけを操作できます（ほかの部屋の操作卓は押せません）。操作は従来どおり実験の操作列として記録されます。
- **役割ごとに足した設備**：データ記録装置（記録済みデータ量）、酸素タンク（残量）、最大値の表示器（電気の使用量の最大値）、冷却水の流量計（冷却水の流量）。どれも既存の信号を読むだけで、船の電気と熱の計算には影響しません。故障の再現条件と修復条件は変わっていません。
- **設備パネル**：設備をクリックすると、説明のあとに次の3つを分けて表示します。追加の操作なしで、いつでも現在値が見えます。
  - **入力（この設備が受け取る値）**：値の名前と種類・単位、送り元の設備、最新の受信値、受け取った時刻。操作卓ではクルーの指示、放熱器では船外環境が入力です。
  - **出力（この設備が送る値）**：値の名前、いま計算した値、送り先の設備、相手に届いた最新の値の送信時刻。
  - **プロパティ（この設備の設定と内部状態）**：設定（変更できるものはその場で変更＝修理、できないものは値だけ）と、どこにも送らない内部状態（例：実験装置の出力制限中フラグ）。名前は配置図データの `properties` で付けます。
- 設備を選ぶと、その入力と出力が時系列グラフと Messages タブにも出ます（サンプルは全接続の最新値を持つので、実験の再生でも最初から描けます）。
- 以前の「計測点（3本）」と「診断（3回）」は、操作の意味が分かりにくいため削除しました。
- 時間操作は Run / Pause / Reset / Restart と 1x/4x/8x のみです。実験の記録・再生・変種・比較は既存のまま使えます。
- 宇宙船は Mode A/B を持ちません。旧PoC（抽象）の2ページは選択肢の下に残しています（そちらは従来の階層グラフ）。
- 故障箇所の自動着色・自動列挙はしません（契約違反の報告先だけが警告表示になります）。
- 保存は v16 のままです。計測点・診断があった時期の保存も読み込めます（その部分は無視します）。

## 6. 評価について

再現条件の発見と因果説明の二段階の洞察が起きるか、宇宙船の意味が推理を助けるかは、**初見プレイテストをしていないため未検証**です。テストで確かめたのは、仕様どおりに動くこと、再現・対照の操作列が決定論的に同じ結果になること、修復判定が代替修復を受理し帳尻合わせを落とすことまでです。
