# 宇宙船PoC 設計者用資料（ネタバレ）

> 2026-10-19 以降、案件は3つの不具合を持つ「カナリア級の連続爆発」に変わりました。現在の解答と再現条件は [SHIP_CLASS_PLAN.md](SHIP_CLASS_PLAN.md) を参照してください。この資料は、不具合A（冷却水ポンプの優先度）の調査経路として残しています。

**プレイ前に読まないでください。** この内容はプレイ画面の初期表示に出していません。ヒント（4段階）と Solution の解説にだけ、段階的に出します。

案件ID：`ship-cooling-01` ／ 題：「冷却が足りないのに、ポンプは正常を報告する」

## 真の原因

配電盤の設定で、冷却水ポンプが**ふつうの機器**（`pdu.pumpEssential = 0`）として登録されています。仕様では最優先の機器（1）です。

- 最優先の機器は毎 tick、容量 5.5 kW の範囲で申請どおりに割り当てられます。
- ふつうの機器は早い者順です。ほかのふつうの機器が前の tick までに確保した電力は、その機器の要求が下がるまで取り上げられません。
- そのため、ポンプが流量を上げる前に 酸素 増産（4 kW）が始まると、酸素 製造装置が船の電気の空きを先に確保し、ポンプの使ってよい電力は 5.5 − 4 = 1.5 kW（12 L/min）で頭打ちになります。
- ポンプの状態報告は「流量指示を受けているか」しか見ないため、「運転中」のままです。

### 因果の流れと二つの時点

| 時点（再現手順） | 内部で起きること | 外から見えること |
|---|---|---|
| t=8 | 実験運転を指示 | — |
| t=10 | 酸素 増産を指示（ポンプはまだ 10 L/min・1.25 kW） | 酸素 製造量が 2 L/min に上がる（t≈15） |
| t≈15 | ポンプの電力申請が 3.7 kW に上がるが、使ってよい電力は 1.5 kW のまま（**内部状態の変化が先**） | 電気の使用量が 5.5 kW に張り付く。冷却水ポンプは「運転中」 |
| t=31 | 電子機器が 40 °C を超える | 安全監視用の電子機器の温度が契約違反（**遅れて現れる症状**） |
| t=46 | 温度報告が 42 °C に達し、実験装置が過熱防止に入る | 実験装置の状態が「出力制限」 |
| t=53〜74 | 発熱が減って温度が下がり、復帰 | 回復 |
| t=87〜 | 再び実験運転で温度が上がる（繰り返す） | 断続的な異常 |

最初の症状まで約 20 tick、実験装置の出力制限まで約 35 tick 遅れます。この遅れが「一定時刻後に壊れる」ように見えますが、実際には増産を始めた時点のポンプの割り当てで決まっています。

## 操作列（開発者向けテストで使用。`src/spaceship/index.ts` の `designerRuns`）

| 名前 | 操作 | 結果 |
|---|---|---|
| 再現 | t=8 実験運転、t=10 酸素 増産 | t=31 温度異常、t=46 出力制限、以後繰り返す |
| 対照（1条件だけ変更） | t=8 実験運転、t=30 酸素 増産 | 異常なし（ポンプが先に約 3 kW を確保している） |
| 増産が先 | t=4 酸素 増産、t=20 実験運転 | t=45 温度異常、t=58 出力制限 |

境目：実験運転の開始から 4 tick 以内に増産を始めると必ず再現し、8 tick 以上あとなら再現しません。その間（5〜7 tick）は、実験運転を始めた時刻と温度センサーの測る間隔（4 tick ごと）の位相で変わります。最初の上昇が報告されるまで、ポンプは流量を上げないためです。増産を先にした場合は間隔によらず再現します。

## レポートの作り（R1〜R3）

- R1：再現手順の日。酸素 増産の時刻は欠落。温度異常・出力制限・「運転中」の報告だけを出す。
- R2：対照手順の日。同じ実験計画で問題なし。
- R3：両日の電気の使用量（どちらも 5.5 kW 付近）と 酸素 製造量（異常の日 2.0、正常の日 約 1.4 L/min）。**異常の日のほうが 酸素 が多い**ことが、電力の取り合いに気づく手掛かりです。

## 想定する調査経路

1. 冷却管理室の表示で、温度異常が実験運転中に出ること、ポンプが「運転中」と言っていること、冷却水の流量が正常の日より小さいこと（R3）を確認する。
2. 実験運転と 酸素 増産の順番・間隔を変えた実験と変種を作り、「増産を早く始めた日だけ」再現することを見つける（再現条件の発見。コンソールだけでできる）。
3. 設備の説明と入力の送り元から、酸素 製造装置と冷却水ポンプが同じ配電盤から電力をもらっていることを読み取る（配置図では生命維持区画と冷却装置区画は離れていて、電源室だけが両方につながる）。
4. 冷却水ポンプの入力「冷却水の流量の指示」と出力「冷却水の流量」を比べ、指示 30 L/min に対して流量 12 L/min しか出ていないことを見る。
5. 配電盤の入力「ポンプの電力申請」と出力「ポンプが使ってよい電力」を比べ、要求 3.75 kW に対して許可 1.5 kW が、増産の数 tick 後から続いていることを時系列か受け渡しの履歴で確かめる。
6. 配電盤のプロパティで、冷却水ポンプの優先度がふつうの機器（0）になっていること、説明（最優先の機器）と食い違うことを確かめる（原因の説明）。

計測点と診断を削除したため、全設備のプロパティを順に見て説明と食い違う設定を探す近道は、ふさいでいません。これで推理が成り立つか（設定の食い違いだけを見て直してしまわないか）は、プレイテストで確かめる必要があります。

### 用意した誤誘導と反証

| 仮説 | 反証の実験 |
|---|---|
| 温度センサーの報告が古い（4 tick ごと） | 測る間隔を 1 にしても再現する |
| 冷却調整装置のゲインが低い | ゲインを 10 にしても再現する（指示は上がるが流量は頭打ち） |
| ポンプが故障している | ポンプは使ってよい電力どおりの流量を出している（使ってよい電力 ÷ 0.125） |
| 船の電気の過負荷 | 電気の使用量は上限 5.5 kW を超えていない |

## 修復判定

判定は System の合格基準と公開検証ケース 13 件だけで行い、原因ノードを編集したかは見ません。

| 修復 | 結果 | 理由 |
|---|---|---|
| 冷却水ポンプの優先度を 1（最優先の機器）に戻す | 合格（直接修復） | 仕様どおり、ポンプが毎 tick 先に満たされる |
| 酸素 増産時に申請する電力を 3.5 kW 以下にする | 合格（代替修復） | 増産が先でもポンプに 2 kW 以上残る。酸素 は契約の 0.8 L/min 以上を保つ |
| 冷却の最低流量を 20 L/min 以上にする | 合格（代替修復） | 増産より前にポンプが 2.5 kW を確保する |
| 冷却の目標温度を下げる（25 °C など） | 合格（代替修復） | 待機中から流量が多く、同じ理由でポンプが先に電力を確保する |
| 配れる電力の合計を上限より上げる（7 kW） | 不合格 | 電気の使用量が上限 5.5 kW を超える |
| 過熱防止が働く温度を上げる（50 °C） | 不合格 | 電子機器の温度が 40 °C を超える |
| 温度センサーの校正をずらす（−5 °C） | 不合格 | 安全監視用の温度は偽装できない |
| センサーの測る間隔だけ短くする | 不合格 | 頭打ちは変わらない |
| 温度1 °Cあたりに増やす流量だけ上げる | 不合格 | 頭打ちは変わらない |
| 実験装置を止める・待機にする | 不合格 | 実験装置の可用性の契約に反する |
| 最大流量を 40 L/min にする | 不合格（正常系でも） | ポンプが 5 kW まで要求し、酸素 の契約を割る |

## 変更要求書のサンプルからの調整

- 主要原因は「供給電力と冷却動作の不一致」に絞りました。古いセンサー報告は、再現の境目（何 tick 以内か）を決める副次要因として残し、主原因ではないことを反証できるようにしています。
- 「運転制御」モジュールは指示を中継するだけになるため置かず、指示を System の入力にしました。代わりに、熱の源で過熱防止を持つ「実験装置」を5番目のモジュールにしました。
- ふつうの機器どうしの規則は、最初は「要求が変わったときだけ割り当てを見直す」案でしたが、ポンプの指示が上限に張り付くと増産をやめても回復しない挙動になり、対照実験が読みにくくなったため、「確保済みの分は取り上げない」早い者順に変えました。
