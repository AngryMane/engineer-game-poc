# 宇宙船PoC 設計者用資料（ネタバレ）

**プレイ前に読まないでください。** この内容はプレイ画面の初期表示に出していません。ヒント（4段階）と Solution の解説にだけ、段階的に出します。

案件ID：`ship-cooling-01` ／ 題：「冷却が足りないのに、ポンプは正常を報告する」

## 真の原因

配電盤の設定で、冷却ポンプが**一般負荷**（`pdu.pumpEssential = 0`）として登録されています。仕様では重要負荷（1）です。

- 重要負荷は毎 tick、容量 5.5 kW の範囲で要求どおりに割り当てられます。
- 一般負荷は先着順です。ほかの一般負荷が前の tick までに確保した電力は、その機器の要求が下がるまで取り上げられません。
- そのため、ポンプが流量を上げる前に O₂ 増産（4 kW）が始まると、O₂ 生成装置が主バスの空きを先に確保し、ポンプの給電許可は 5.5 − 4 = 1.5 kW（12 L/min）で頭打ちになります。
- ポンプの状態報告は「流量指令を受けているか」しか見ないため、「運転中」のままです。

### 因果の流れと二つの時点

| 時点（再現手順） | 内部で起きること | 外から見えること |
|---|---|---|
| t=8 | 実験運転を指令 | — |
| t=10 | O₂ 増産を指令（ポンプはまだ 10 L/min・1.25 kW） | O₂ 生成量が 2 L/min に上がる（t≈15） |
| t≈15 | ポンプ電力要求が 3.7 kW に上がるが、給電許可は 1.5 kW のまま（**内部状態の変化が先**） | 主バス負荷が 5.5 kW に張り付く。冷却ポンプは「運転中」 |
| t=31 | ラックが 40 °C を超える | 独立監視の機器ラック温度が契約違反（**遅れて現れる症状**） |
| t=46 | 温度報告が 42 °C に達し、ペイロードが熱保護に入る | ペイロード状態が「制限運転」 |
| t=53〜74 | 発熱が減って温度が下がり、復帰 | 回復 |
| t=87〜 | 再び実験運転で温度が上がる（繰り返す） | 断続的な異常 |

最初の症状まで約 20 tick、ペイロードの制限運転まで約 35 tick 遅れます。この遅れが「一定時刻後に壊れる」ように見えますが、実際には増産を始めた時点のポンプの割り当てで決まっています。

## 操作列（開発者向けテストで使用。`src/spaceship/index.ts` の `designerRuns`）

| 名前 | 操作 | 結果 |
|---|---|---|
| 再現 | t=8 実験運転、t=10 O₂ 増産 | t=31 温度異常、t=46 制限運転、以後繰り返す |
| 対照（1条件だけ変更） | t=8 実験運転、t=30 O₂ 増産 | 異常なし（ポンプが先に約 3 kW を確保している） |
| 増産が先 | t=4 O₂ 増産、t=20 実験運転 | t=45 温度異常、t=58 制限運転 |

境目：実験運転の開始から 4 tick 以内に増産を始めると必ず再現し、8 tick 以上あとなら再現しません。その間（5〜7 tick）は、実験運転を始めた時刻と温度センサーの報告周期（4 tick ごと）の位相で変わります。最初の上昇が報告されるまで、ポンプは流量を上げないためです。増産を先にした場合は間隔によらず再現します。

## レポートの作り（R1〜R3）

- R1：再現手順の日。O₂ 増産の時刻は欠落。温度異常・制限運転・「運転中」の報告だけを出す。
- R2：対照手順の日。同じ実験計画で問題なし。
- R3：両日の主バス負荷（どちらも 5.5 kW 付近）と O₂ 生成量（異常の日 2.0、正常の日 約 1.4 L/min）。**異常の日のほうが O₂ が多い**ことが、電力の取り合いに気づく手掛かりです。

## 想定する調査経路

1. 乗組員コンソールで、温度異常が実験運転中に出ること、ポンプが「運転中」と言っていることを確認する。
2. 実験運転と O₂ 増産の順番・間隔を変えた実験と変種を作り、「増産を早く始めた日だけ」再現することを見つける（再現条件の発見。コンソールだけでできる）。
3. 設備の説明と入力の送り元から、O₂ 生成装置と冷却ポンプが同じ配電盤から電力をもらっていることを読み取る（配置図では生命維持区画と熱制御区画は離れていて、電源室だけが両方につながる）。
4. 冷却ポンプの入力「冷却流量指令」と出力「冷却液流量」を比べ、指令 30 L/min に対して流量 12 L/min しか出ていないことを見る。
5. 配電盤の入力「ポンプ電力要求」と出力「ポンプ給電許可」を比べ、要求 3.75 kW に対して許可 1.5 kW が、増産の数 tick 後から続いていることを時系列か受け渡しの履歴で確かめる。
6. 配電盤のプロパティで、冷却ポンプの負荷区分が一般負荷（0）になっていること、説明（重要負荷）と食い違うことを確かめる（原因の説明）。

計測点と診断を削除したため、全設備のプロパティを順に見て説明と食い違う設定を探す近道は、ふさいでいません。これで推理が成り立つか（設定の食い違いだけを見て直してしまわないか）は、プレイテストで確かめる必要があります。

### 用意した誤誘導と反証

| 仮説 | 反証の実験 |
|---|---|
| 温度センサーの報告が古い（4 tick ごと） | 報告周期を 1 にしても再現する |
| 冷却制御のゲインが低い | ゲインを 10 にしても再現する（指令は上がるが流量は頭打ち） |
| ポンプが故障している | ポンプは給電許可どおりの流量を出している（許可 ÷ 0.125） |
| 主バスの過負荷 | 主バス負荷は定格 5.5 kW を超えていない |

## 修復判定

判定は System の運用契約と公開検証ケース 13 件だけで行い、原因ノードを編集したかは見ません。

| 修復 | 結果 | 理由 |
|---|---|---|
| 冷却ポンプの負荷区分を 1（重要負荷）に戻す | 合格（直接修復） | 仕様どおり、ポンプが毎 tick 先に満たされる |
| O₂ 増産時の要求電力を 3.5 kW 以下にする | 合格（代替修復） | 増産が先でもポンプに 2 kW 以上残る。O₂ は契約の 0.8 L/min 以上を保つ |
| 冷却の最低流量を 20 L/min 以上にする | 合格（代替修復） | 増産より前にポンプが 2.5 kW を確保する |
| 冷却の目標温度を下げる（25 °C など） | 合格（代替修復） | 待機中から流量が多く、同じ理由でポンプが先に電力を確保する |
| 割り当て容量を定格より上げる（7 kW） | 不合格 | 主バス負荷が定格 5.5 kW を超える |
| 熱保護の作動温度を上げる（50 °C） | 不合格 | ラック温度が 40 °C を超える |
| 温度センサーの校正をずらす（−5 °C） | 不合格 | 独立監視の温度は偽装できない |
| センサーの報告周期だけ短くする | 不合格 | 頭打ちは変わらない |
| 制御ゲインだけ上げる | 不合格 | 頭打ちは変わらない |
| ペイロードを止める・待機にする | 不合格 | ペイロードの可用性の契約に反する |
| 最大流量を 40 L/min にする | 不合格（正常系でも） | ポンプが 5 kW まで要求し、O₂ の契約を割る |

## 変更要求書のサンプルからの調整

- 主要原因は「供給電力と冷却動作の不一致」に絞りました。古いセンサー報告は、再現の境目（何 tick 以内か）を決める副次要因として残し、主原因ではないことを反証できるようにしています。
- 「運転制御」モジュールは指令を中継するだけになるため置かず、指令を System の入力にしました。代わりに、熱の源で熱保護を持つ「科学ペイロード」を5番目のモジュールにしました。
- 一般負荷どうしの規則は、最初は「要求が変わったときだけ割り当てを見直す」案でしたが、ポンプの指令が上限に張り付くと増産をやめても回復しない挙動になり、対照実験が読みにくくなったため、「確保済みの分は取り上げない」先着順に変えました。
