# 実装・説明文の確認（2026-10-17）

確認対象：イベントエンジン、出力条件・採点、全シナリオ、数式表示、接続・編集表示、再実行・保存、解説、README。

## 確認して修正した問題

1. **無効な接続の値が計算に残る**
   - 受信済み値が入力に残り、配送待ちイベントも届いていた。
   - 無効化で受信キャッシュと配送待ちを除外し、計算からも除外。完了済みの入出力表示は次の計算まで維持する。再有効化後は次の出力・問い合わせから受信する。
   - 数式から無効な参照元を除外し、グラフでも「無効」と表示する。
2. **再実行と採点の初期状態が異なる**
   - 採点は手動編集した状態値を初期値に適用するが、再実行では失われていた。
   - 同じ初期状態の生成処理を利用し、接続の受信キャッシュ・初期ポート表示も同期する。初期の接続観測値が常に0になる不整合も修正。
3. **設定・入力変更後にも前の検証結果が残る**
   - 安定待ち時間はリセットされても、画面の検証結果が古いままだった。
   - 実際に変更された時点で検証結果キャッシュを破棄する。
4. **正常設定でN01を繰り返し操作すると誤判定される**
   - 故障なしでt=0に1、t=30に0、t=40に1とすると、N04はt=44で4になる一方、条件はt=51まで10を要求していた。
   - N01→N06の関係E25を追加し、N06がN01から0を受信したら次の計算で蓄積を0に戻す。処理はN06の明示的なswitch式で実施し、接続は計算しない。
   - 既存の正常11ステップ／故障33ステップの応答を維持。繰り返し変更を公開検証ケースへ追加した。
5. **説明文の不整合**
   - チュートリアルの解説が出力8・完了済みに固定され、故障なしでも故障原因を表示していた。入力や閲覧時点に依存しない説明へ修正。
   - 状態編集履歴をnode.state.key表記へ統一。状態参照の説明に手動編集を含める。
   - 待機時間・再実行・接続無効化の説明を実装に合わせ、存在しない未観測の関係への言及とREADMEの旧用語を除去。
6. **長時間観測時の描画失敗の可能性**
   - Math.max/minへ全測定値を展開していたため、十分な件数で引数上限を超える。
   - 配列のreduceで範囲を計算する。
